# libbitcoin-database — Architecture documentation

This is a top-down, source-anchored description of libbitcoin-database, the
store beneath libbitcoin-node. It covers the storage primitives (heads,
bodies and maps), the tables built from them, the memory-mapped storage and
its recovery model, and the query layer that the node uses.

The relational concepts (natural, foreign and search keys, navigation versus
search, append-only bodies published by heads, recoverability, and
reliability) are from the 2021 [design
document](libbitcoin-v4-relational-database.pdf) for the version 4 store.

Every behavioural claim is anchored with `file:line` references into the
C++ source. The citations were verified against libbitcoin-database master
at commit `d29fa3df` (2026-10-20). Paths are relative to
`include/bitcoin/database/` unless they begin with `src/`.

## Recommended reading orders

### For a new contributor
**00 → 01 → 02 → 03**, then **05 §2–§3** for how a block is written and
confirmed. Read **04** when working on store lifecycle or performance.

### For a formal-verification reader
**01** states the reliability model. **02 §5** and **04 §5** give the publication model: every write becomes
visible through a single atomic cell or size store, and recovery is a head
snapshot over append-only bodies. **05 §2** is the archival commit order
that the node's `organizeN`/`validateN`/`confirmN` faults rely on. The
numbered invariants are listed below.

### For a node reader
The [node architecture](../architecture/index.html) treats the store as an
oracle. **05** is the interface it calls, and **04 §4–§6** are the
suspend, disk-full and snapshot behaviours that `chaser_storage` and
`chaser_snapshot` drive.

## Honest caveats

1. **No build verification.** Citations are textual and were re-grepped
   during writing; nothing was built or executed for this documentation.
2. **Comments in `store.hpp`.** Several member comments there name an
   older primitive (for example input and txs as "slab hashmap", strong
   and state as "record hashmap"). These pages follow the type
   declarations in `tables/`.
3. **Consensus rules** (script, BIP30/34/68 checks) live in
   libbitcoin-system. [`05-queries`](queries) describes the store
   reads behind them, not the rules.
